# 文件关联区模板

> 每份新建的现行Markdown文件必须在创建时同步填写文件关联。物理文件夹节点只说明文件放在哪里，不能代替本文件与规则、纲线、人物、研究、正文和核验记录之间的业务关系。

## 一、非正文文件使用区

把下列区块放在文件末尾。只链接已经存在的文件；尚未创建的下游写明`待创建：预期路径`，不得制造断链。

```markdown
## 文件关联

### 上游依据

- [文件名](相对路径)：本文件从它继承什么。

### 同层互证

- [文件名](相对路径)：与本文件核对什么，冲突时谁优先。

### 下游去向

- [文件名](相对路径)：本文件的哪项结论进入该文件。
- 待创建：`预期路径`——创建后补成真实链接。

### 回写与失效

- 本文件变化后必须复核：
- 上游变化时本文件哪些结论自动失效：
```

## 二、工作单元与正式正文使用区

正文首行使用YAML属性，不把流程说明混入读者正文；合订TXT继续按版本规则过滤YAML。属性中的内部链接必须指向真实文件。

```yaml
---
文件类型: 工作单元W／正式章C
所属卷: 第XX卷《卷名》
卷纲: "[[02_写作库/04_卷纲/第XX卷_卷名]]"
细纲: "[[02_写作库/05_细纲/第XX卷_卷名]]"
执行入口: "[[02_写作库/06_当前卷执行包/第XX卷_卷名/00_第XX卷执行入口]]"
来源工作单元:
  - "[[WXXX_内部工作名]]"
前一正文: "[[第XXX章_章名]]"
后一正文: 待创建
人物卡:
  - "[[03_人物资料库/分类/卡号_人物名]]"
研究与任务卡:
  - "[[相对库根路径]]"
核验记录:
  - "[[05_核验库/相对路径]]"
修改记录: 无／待创建／"[[05_核验库/相对路径]]"
---
```

第一章可把`前一正文`写成`本卷起点`；最后一章在作者扶正前把`后一正文`写成`下一卷待创建`。不得为了让表格好看而链接不存在的文件。

## 三、各类文件最低关联

| 文件类型 | 最低必须链接 |
|---|---|
| 项目入口／当前状态 | 规则总索引、母纲、当前卷执行入口或明确停止点 |
| 规则 | 规则总索引、关联规则、至少一个使用该规则的核验入口 |
| 母纲／年表／跨卷台账 | 三者互链，并链接当前卷纲或项目总索引 |
| 卷纲 | 母纲、年表、跨卷台账、对应细纲、关键人物卡／研究卡 |
| 细纲 | 对应卷纲、执行入口、人物卡、研究／任务卡、细纲核验卡 |
| 人物卡 | 人物库索引、直接关系人物卡、采用该人物的卷纲／细纲或状态台账 |
| 研究卡 | 研究索引、证据来源登记、实际采用它的规则／任务／纲线 |
| W工作单元 | 卷纲、细纲、执行入口、上一W、人物／任务卡、覆盖卡与逐句表 |
| C正式章 | 卷纲、细纲、来源W、前后C、人物／任务卡、覆盖卡、逐句表和修改记录 |
| 核验卡／修改记录 | 被核对象、触发规则、上一阶段证据、修复后的新对象或下一核验 |
| 索引／台账 | 被登记文件；被登记的现行文件也必须反向链接本索引／台账 |

## 四、创建与改名硬门

1. 新文件正文内容与文件关联必须在同一次创建动作中完成；禁止先建孤立文件、以后再说。
2. 关联不是堆路径。每条链接后必须写清继承、互证、回写或失效关系。
3. 已存在的文件发生改名或移动时，同步更新所有现行反向链接，再运行断链检查和Obsidian目录树重建。
4. 文件只有目录节点入链、却没有任何业务关联，状态只能记为`结构已入库，业务关联未完成`，不得交付。
5. `.csv`、`.txt`、图片、脚本等不能自行写Markdown关联区的文件，必须由对应Markdown索引、任务卡或注册表链接并说明用途。
