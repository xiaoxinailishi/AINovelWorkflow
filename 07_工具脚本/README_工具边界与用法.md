# 工具边界与用法

## 一、绝对边界

这些脚本只做机械工作：拆句、重建表格、检查哈希、按段落映射重组正式章、合成TXT、重建Obsidian全文件直链索引。它们不能判断人物是否自然、情节是否好看、规则是否真正满足，也不能替代作者扶正。

运行前应复制到具体项目的`06_工具/脚本`，并在项目配置里填写真实路径。不要直接在通用模板库里对具体小说运行。

## 二、脚本

| 脚本 | 用途 | 关键门禁 |
|---|---|---|
| `Initialize-CommonRuleLibrary.ps1` | 完整复制并逐文件核对通用规则、语言库和四份流程硬规则 | 目标非空时拒绝覆盖；输出迁移清单和SHA |
| `New-SentenceAuditTable.ps1` | 从W或C正文生成逐句候选表 | 生成后仍须逐句人工判断 |
| `Rebase-SentenceAuditTable.ps1` | 正文修改后按W/C编号重建表 | 未匹配句必须重新核验 |
| `Test-SentenceAuditTable.ps1` | 检查表格结构、SHA和待核项 | 只证明表结构，不证明文学质量 |
| `Build-FormalVolumeFromParagraphMap.ps1` | 把归档W按段落映射重组为C章 | 必须先有人工确认的映射配置；字数上下限由项目参数传入 |
| `Build-FormalVolumeTxt.ps1` | 按清单合成整卷TXT | 卷末标记正则由项目传入；输出必须在项目根目录内 |
| `Build-ObsidianVaultIndex.ps1` | 为每个物理文件夹生成节点笔记；让库入口同时直连目录树总入口和顶层文件夹，再连接子文件夹与本层文档；公开发行时可用`-RootLabel`写入脱敏显示名 | 只清理固定生成目录中的`目录__*.md`；只替换库入口内带标记的自动生成区；排除`.obsidian`、`.git`、`.trash`；不替代项目入口、规则索引或文件注册表 |
| `Test-FileAssociations.ps1` | 只读统计现行Markdown是否填写语义关联、是否至少含一个出链候选，并列出存量缺口 | 不自动补链接、不推断业务语义；默认只报告，`-FailOnMissing`才以缺口阻断；排除历史层和机械文件夹节点 |
| `Build-NovelWritingSkillPackage.ps1` | 从已经脱敏并验收的发行根目录生成Codex或扣子Skill ZIP，重写Skill引用路径，清除已排除根临时文件在目录索引中的残留链接，并检查frontmatter、本机绝对路径；ZIP只写UTF-8、NFC、正斜杠文件条目，完成干净解压SHA复验 | 不得直接把含私人路径、具体小说资产或未验收规则的工作目录公开；不能代替Codex插件清单验收 |

## 三、推荐调用顺序

1. 新项目初始化时先完整迁移通用规则与语言库并核对清单；
2. W写完后生成W逐句表；
3. 人工逐句核验；
4. 修改正文时记录修改前后并重建逐句表；
5. 整卷W完成并通过连续性检查后，人工制定段落映射；
6. 生成C正式章；
7. 对C重新生成逐句表并全量核验；
8. 生成TXT并核对来源SHA。
9. 项目文件增删改名后，重建Obsidian目录树，检查“物理文件夹=文件夹节点”及“普通文件=所属文件夹直链”。
10. 新建或调整现行Markdown后，运行`Test-FileAssociations.ps1`；逐项人工补上游、互证、下游和回写，不得让脚本代填。
11. 发布Skill前先生成脱敏发行副本并完成链接、隐私和SHA验收，再用`Build-NovelWritingSkillPackage.ps1`分别构建目标格式；不得直接复用旧ZIP中的references。

示例配置见`配置模板`。示例中的字数仅为演示，不是通用硬规则。
