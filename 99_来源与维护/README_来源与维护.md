# 来源与维护

## 一、提炼来源

本模板库于2026-08-15从一套正在使用的长篇小说工程中只读提炼。提炼目标是保存可复用的文件链路、规则判断、双词典方法、逐句核验、版本存证和卷终流程；具体书名、人物、年代、世界观、剧情和作者裁决不进入通用层。

来源项目仍是其自身的唯一权威，本模板库不会反向修改或覆盖来源项目。

## 二、维护原则

1. 先修通用模板，再由具体项目决定是否升级；
2. 模板升级不得静默覆盖项目冻结版本；
3. 新增通用规则必须更新规则总索引、19份迁移清单、核验卡模板和初始化脚本；
4. 新增流程阶段必须同步入口流程图、阶段产物表、项目骨架和卷终核验；
5. 改脚本后必须做语法解析和临时项目实测；
6. 参考小说只能用于归纳语言风险与方法，不复制其受版权保护的表达。
7. 新增任何资产必须更新入口09号完整资产登记、03号源文件去向、逐文件SHA清单和验收报告；不能只放文件、不留登记。
8. AI执行入口只能加强预检、路由和验收闸门，不得把“快速模式”、摘要判断、旧校验卡或批量扫描包装成正式完成。
9. Codex插件和扣子Skill必须从同一份已脱敏公开发行基线分别构建；禁止直接复用旧ZIP，也禁止把两端不兼容的frontmatter字段混入同一发行文件。
10. 发行构建必须排除`.git`、`.obsidian`、`.trash`、`dist`和`发行包`自身，防止递归套包与本机状态泄漏。
11. `.obsidian/workspace.json`和`graph.json`等属于软件运行状态，会随界面操作改变；它们只进入Obsidian入库记录，不进入内容SHA清单。
12. 轻量练习只降低交付层级，不得被包装成正式验收；协作模式只分配责任，不得转移作者扶正权；失败恢复必须保留现场并使旧证据按影响范围失效。
13. 周易思维只用于时位、进退、损益、变化、言行与留尽的结构复核，不用于占卜断事、随机配卦或把人物统一写成含蓄腔；卷纲、整卷＋逐W细纲在常规核验后独立留证，每个W和每个C则在老书虫全文章节核验前先完成周易正文复核，后续改文须对新SHA从周易重新起跑。
