## 二、三种模式

| 责任项 | A 作者主写，AI只核验 | B 单主写AI，作者逐阶段放行 | C AI主写，作者最终复核 |
|---|---|---|---|
| 正文初稿 | 作者 | 同一AI主写窗口 | 同一AI主写窗口 |
| 正文改写 | 作者执行，AI只提具名问题，除非另获授权 | AI在当前授权范围内执行 | AI在当前授权范围内执行 |
| 规则与语义判断 | AI逐项核验，作者裁决冲突 | AI逐项核验，作者裁决冲突 | AI逐项核验，作者裁决冲突 |
| 证据填写 | AI只能依据当前真实文件填写 | 主写AI填写并自查 | 主写AI填写并自查 |
| 阶段放行 | 作者 | 作者在每个约定阶段明确放行 | AI可推进到预定停止点，越过停止点仍须作者放行 |
| 最终扶正 | 仅作者 | 仅作者 | 仅作者 |
| 并行协作 | 仅经授权的机械检查或独立资料 | 同左 | 同左 |
| 必须回写 | 问题清单、核验卡和受影响台账 | 正文、核验卡、修改记录和受影响台账 | 正文、核验卡、修改记录和受影响台账 |

“AI主写”只说明执行分工，不代表AI获得新的写入权限、阶段放行权或作者扶正权。任何并行结果都只是候选材料，不能直接写成正式通过证据。

## 四、协作硬门

1. 一个W或C只有一个主写窗口；不得把正文拆给多个执行者后拼接，并用一次汇总审读冒充逐章生产。
2. AI只核验模式下，未经作者新增授权不得直接改正文。
3. AI主写模式下，AI不得自行放宽规则、补写`TX待作者裁决`或扩大允许修改的文件范围。
4. 任何模式都必须执行项目现行的写前、写中、写后、W、C和卷终证据门；协作配置不是快速验收通道。
5. 模式变化立即停止当前对象，记录旧模式停止点、已生成文件、当前SHA和证据有效范围，再由作者确认新模式。
6. 出现冲突、越权或证据失效时，立即转入[失败模式与恢复手册](../00_模板库入口/12_失败模式与恢复手册.md)。

## 六、提交前确认

- [ ] 本轮模式、责任人、允许文件和停止点明确；
- [ ] 正文只有一个主写窗口；
- [ ] 当前对象要求的规则、语言和逐句证据全部有效；
- [ ] 并行结果已由主写窗口回读原文件并复核；
- [ ] 修改后旧SHA和旧结论已经失效；
- [ ] 作者扶正没有被AI或协作者代签。

任一项未满足，只能报告已完成范围与阻断项，禁止提交正式验收。
