# 小说通用模板库唯一入口

> 本目录是所有长篇小说可复用的写作、核验与存证模板库，不属于任何一本具体小说。  
> 模板变量统一写成`{{变量名}}`。建立新书时应复制模板，不得把具体小说正文、人物或作者裁决反写进本模板库。

公开项目介绍与总流程图见[GitHub项目主页](../README.md)。本文件仍是AI执行和模板使用的唯一入口。

## 一、第一次使用的固定顺序

1. 完整阅读[通用模板库完整交接文档](10_通用模板库完整交接文档.md)，先理解全库层级、文件关系、Obsidian用法和逐卷到结局的完整循环。
2. 完整阅读[新小说初始化顺序](01_新小说初始化顺序.md)。
3. 完整阅读[通用文件链路图](02_通用文件链路图.md)。
4. 复制`03_新书项目骨架`到新书目录，替换全部模板变量。
5. 将`01_通用规则库`和`02_语言与风格库`复制进新项目规则库。
6. 将03、04、05、06号入口文档中的4份现行流程硬规则迁入新项目入口；推荐用初始化脚本一次完成第5、6步并核对SHA。
7. 将`04_写作模板库`、`05_人物与设定模板库`、`06_核验模板库`复制到项目对应位置。
8. 按[每卷严格生产流程](03_每卷严格生产流程.md)工作，不得越级生成正文。

完整资产范围见[通用资产清单](08_通用资产清单.md)；逐层“已放／此次补放／故意不放／仍待裁决”状态见[完整资产登记与缺口清单](09_完整资产登记与缺口清单.md)。

## 二、通用库的八个有效层

| 层 | 作用 | 能否写具体小说内容 |
|---|---|---|
| `00_模板库入口` | 使用顺序、文件链路、全卷流程 | 否 |
| `01_通用规则库` | 所有小说都必须判断的通用规则 | 否 |
| `02_语言与风格库` | 对白、旁白、中文母语和去AI腔 | 只允许通用例句 |
| `03_新书项目骨架` | 新项目空目录和入口占位文件 | 只填模板变量 |
| `04_写作模板库` | 母纲、年表、卷纲、细纲、工作单元、卷内索引 | 只填模板字段 |
| `05_人物与设定模板库` | 人物卡、关系表、世界观卡、研究卡 | 只填模板字段 |
| `06_核验模板库` | 细纲、全规则、逐句、修改、卷终、扶正核验 | 只填模板字段 |
| `07_工具脚本` | 哈希、逐句表、TXT和结构检查辅助 | 不得自动判定内容通过 |

`99_来源与维护`只记录模板来源、版本和维护日志，不参与具体小说执行。

`.obsidian`、根目录`OBSIDIAN_库入口.md`和`00_Obsidian导航`只负责本机入库与全文件导航，也不构成新的写作规则层。

## 三、不可跳过的原则

- 作者最新明确裁决高于一切模板，但必须写入项目专属规则，不得只留在聊天里。
- 新窗口不得凭聊天记忆写作，必须从项目唯一入口进入。
- 规则总索引登记的每份规则，对每个工作单元和正式章都要从首行读到末行并判断适用性。
- 通用规则库和语言库必须整层迁移并逐文件核对SHA；不得选读、摘要迁移或凭旧窗口记忆补规则。
- 卷纲和逐工作单元细纲未通过核验，不得生成正文。
- 工作单元通过，不等于正式章通过；正式章重组后必须重新核验。
- 机械脚本只能检查结构、数量、哈希和链接，不能代替人工阅读与语义判断。
- 作者未明确扶正，正文不得进入正式正文库。

## 四、新项目必须新增的内容

通用模板不能替代项目专属规则。每本书至少要补：

- 作者最高裁决与禁写项；
- 世界观、时间线、事实与架空边界；
- 主角能力或金手指边界；
- 人物关系、称谓和声线；
- 题材专项规则；
- 正式章字数、卷末标记、标题偏好；
- 本书禁用词、偏好词和参考文本边界。
