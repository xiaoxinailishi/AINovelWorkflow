# 失败模式与恢复手册

> 本手册用于规则冲突、事实矛盾、时间线错位、误覆盖、越权写作和证据失效。恢复目标是保留现场、缩小影响范围、建立新证据，不是把错误悄悄改掉后继续写。

## 一、统一恢复链

```text
立即停写
→ 保存故障现场
→ 标记受影响证据失效
→ 定位最后有效SHA
→ 确定影响范围
→ 取得作者裁决
→ 修复副本或现行稿
→ 对受影响对象重新核验
→ 回写恢复点与台账
→ 满足继续门禁后再生产
```

任何恢复都必须先保留当前故障稿。不得先删除、覆盖、强制回退或批量重命名，再试图从聊天记忆复原。

## 二、故障现场最小记录

- 故障编号：`REC-{{YYYYMMDD-HHMM}}`
- 发现时间与发现人：`{{待填}}`
- 当前项目／卷／W／C：`{{待填}}`
- 当前授权与停止点：`{{待填}}`
- 故障描述：`{{事实，不写推测}}`
- 涉及文件及当前SHA：`{{待填}}`
- 最后已知有效对象及SHA：`{{待填}}`
- 已复制到的历史目录：`{{YYYYMMDD_HHMM_故障恢复前}}`
- 立即失效的卡、表、索引或TXT：`{{待填}}`
- 需要作者裁决：`{{待填／无}}`
- 当前状态：`阻断，禁止继续生产`

历史目录必须包含故障稿、当时有效或声称有效的核验卡、当前状态和一份本记录。脚本只能帮助找哈希、差异和链接，不能替作者判断哪一版剧情有效。

## 三、常见失败模式与救场

### 3.1 W写到一半发现规则冲突

- **立即停止**：不补完场景，不继续下一W。
- **保留**：当前W草稿、W写前区、细纲、触发冲突的规则版本和SHA。
- **失效范围**：本W写中、写后结论全部无效；若冲突来自上游细纲，细纲核验也失效。
- **作者裁决**：决定修改规则、细纲还是当前W；未知处保留`TX待作者裁决`。
- **恢复**：在副本或现行稿中修复，重做W写前基线，再从冲突影响的首句开始逐句重核。
- **继续门禁**：新SHA、写前／写中记录和作者裁决均落盘后，才能继续本W；不得直接写下一W。

### 3.2 C重组发现世界观或人物事实矛盾

- **立即停止**：暂停当前C及所有后续C重组。
- **保留**：全部原W、旧新映射、已生成C、人物卡、世界规则和冲突证据。
- **失效范围**：涉及事实的C覆盖卡、逐句表、卷终连续性结论全部失效；原W是否失效须逐个判断。
- **作者裁决**：明确哪一条事实为现行权威，以及是否反写母纲、年表、人物卡或研究结论。
- **恢复**：先修权威上游，再修受影响C；每个变化的C从标题到末字独立重核。
- **继续门禁**：映射、上游事实、全部受影响C与证据SHA一致，才可继续重组或卷终验收。

### 3.3 卷终发现时间线对不上

- **立即停止**：禁止提交卷终卡、TXT或作者扶正。
- **保留**：本卷全部C、年表、人物状态、交通耗时、每五W复盘和卷终草稿。
- **失效范围**：受影响章及其后依赖该时间点的连续性结论；不能只改总年表。
- **作者裁决**：若多种修复都会改变剧情，作者选择改时间、改事件或改顺序。
- **恢复**：从最早冲突点向后重算，修正文、年表、人物状态、任务与物件台账。
- **继续门禁**：逐章时间、年龄、行程、季节和SHA重新核对，卷终全部证据重建后才能提交。

### 3.4 规则在生产中途更新

- **立即停止**：登记新规则生效时间和适用范围，不把新规则静默套到旧稿。
- **保留**：旧规则版本、旧正文SHA、旧核验卡和作者的升级裁决。
- **失效范围**：由规则变化决定；任何受影响结论都标记旧口径，不得改日期继续使用。
- **恢复**：按[逐句核验与改文失效规则](06_逐句核验与改文失效规则.md)从最早受影响对象重新核验。
- **继续门禁**：规则版本、迁移清单、项目索引和新证据一致。

### 3.5 文件被误覆盖、误删或错放目录

- **立即停止**：不再写入目标目录；先核对回收站、历史目录、Git或其他只读备份。
- **保留**：残留文件、同名冲突文件、时间戳、SHA和恢复来源说明。
- **失效范围**：无法证明来源与完整性的对象及其下游证据全部失效。
- **恢复**：只从可验证来源复制到明确目标；新旧版本并存时先由作者确认现行版。
- **继续门禁**：路径、文件名、内容、业务关联、反向入口和SHA均重新核对。

### 3.6 Obsidian链接、文件名或SHA清单不一致

- **立即停止**：如果只影响导航，可暂停交付但不必否定正文语义；如果链接承担上游证据，则相关验收同时阻断。
- **保留**：变更前路径、变更后路径、引用文件和清单记录。
- **恢复**：修真实文件及其入链／出链，重建物理导航和SHA清单；不得建空文件或假链接消除断链。
- **继续门禁**：业务关系、反向入口、Obsidian导航、资产登记、来源去向、清单和验收报告一致。

### 3.7 AI越过当前授权写作或修改

- **立即停止**：未经授权生成的内容只能进入隔离历史目录，不能当现行稿。
- **保留**：越权文件、触发指令、修改清单和原现行文件SHA。
- **失效范围**：AI越权修改的全部文件及其后续证据。
- **作者裁决**：作者明确选择废弃、只作候选、逐项吸收或重新授权修复。
- **恢复**：未获作者选择前不得把候选内容合并回现行层；获准吸收后也须逐文件重核。
- **继续门禁**：授权原话、合并范围、修改记录和新证据全部落盘。

## 四、恢复完成卡

- [ ] 故障现场已保存到具名历史目录；
- [ ] 最后有效SHA和最早受影响对象已定位；
- [ ] 旧证据已标记失效，没有改日期复用；
- [ ] 需要的作者裁决已落盘；
- [ ] 上游事实、正文、台账、索引和TXT已按影响范围回写；
- [ ] 受影响对象已重新执行规则、双词典、复读和逐句核验；
- [ ] 新SHA、业务关联、反向入口和现行状态一致；
- [ ] 当前项目入口已经写明恢复后的唯一继续点。

任一项未满足，状态保持`恢复中／阻断`，禁止继续下游生产或提交验收。
