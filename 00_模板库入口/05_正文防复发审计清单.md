# 正文防复发错误与机械／人工审计清单

> 状态：当前执行层硬规则。  
> 目的：把另一个窗口写正文时已经反复出现的问题，变成每个工作单元和正式章都必须逐项核验的防复发清单。  
> 核心：机械扫描只找候选，不能代替主写窗口从标题到末字的人工全文阅读；“换几个同义词”不算修复结构。

## 一、适用时点

1. 工作单元动笔前先执行双词典写前调用，写作中分别参照对白、旁白词典；成稿后先脱离细纲，以普通读者身份全文读一遍，再重新打开双词典完成对白专审、旁白专审，随后按本文件和20号手册审计、建立全规则覆盖卡并进入W逐句核验。修完后重做双词典专审并重新全文读一遍，通过才可写下一单元。
2. 每完成5个工作单元：把五个单元连读，检查相邻开头、结尾、重复解释、信息倒灌、时间与物件连续性。
3. 全卷正式重组后：每个正式章重新执行一次，并重新建立正式章全规则覆盖卡和C逐句表，不能沿用工作单元的旧结论。
4. 若发现重复睡醒、重复梦境、同一信息多次首次揭露、相同结尾或整章公文腔，优先整章重构，不做局部换词补丁。

## 二、人工硬停项

出现下列任一项，当前文本不得通过：

| 类别 | 硬停问题 | 正确处理 |
|---|---|---|
| 婴幼儿身体 | 未到相应发育阶段却点头、示意、远距离伸手取物、稳坐久谈、成人式控制哭声 | 按月龄重写动作；物件由成人递到可触范围；成人意识不能越过身体 |
| 时空在场 | 人物未进入现场、隔墙隔院却直接听清，远行者无耗时瞬移 | 补进入、传话、驿递、行程和到达时间，或删去知情 |
| 身体资格 | 产妇宫缩、失血、发热、重伤时长篇议事；伤者下一场立刻恢复 | 缩短并打断对白；按病程和恢复节点延续 |
| 知情来源 | 主角、AI或旁白知道，便让其他人物同步知道 | 写清谁亲见、谁转述、谁只听到半句、谁仍误判 |
| 物件连续 | 同一原件同时在两人手里；复制件无制作过程；封存物突然出现 | 登记持有人、位置、份数、复制者、交接时间和权限 |
| 语言 | 翻译腔、英文语序、残句命令、公文总结、AI万能三段论 | 改成自然中文，让人物把对象、缘由、条件和人情说完整 |
| 称谓关系 | 子女私下机械称父母官职；下属反用亲属称谓；同一场景只按职位不按真实关系 | 先核亲属／婚姻／师徒关系，再核家事或公事，最后核上下级；不同说话者分别用自己的称谓 |
| 突兀重词 | `妖、反、逆、通敌、天命、祥瑞`无来源突然出现，人物只否定一次便再无后续 | 补说词者、听闻渠道和现实后果，或删除；需要延续则登记伏笔与回收区间 |
| 重复 | 同一梦醒、同一结论、同一人物介绍、同一“众人停下”反应再次出现 | 删除或让第二次产生新信息、新选择、新代价 |
| 关键新增 | 无前置记忆、亲缘、技能、官职、死亡、病因、证据或物件 | 回到事实双轴，标待确认并补来源；不能临场硬塞 |
| 授权链 | 无权限人物掌握足以改变组织或世界的关键信息，却没有送入有效决策链 | 通过监护人、师长、上级、组织、文书、试验或可信证据让信息进入有权者手中 |
| 章节价值 | 删除整章后人物、信息、关系、物件、权限和危险都不变 | 删、并、重构，或补足不可替代变化 |

## 三、中文母语与去AI腔专项

以下不是“建议词表”，而是已出现过的复发问题：

1. 写“一个字也没有少”，不写“少一个字也没有”。
2. 写“她今夜只负责一件事”，不写“她今夜只守一件”。
3. 不写“其余的由我们接”“她方才说的三句就够了”一类故意削短、缺中心词的台词。人物可以说：“娘娘只管把话说清，后面的事由我们来办。”
4. 不写“屋里人都停下了手里的活”“没人趁这时候问话”“这话问得直”等旁白替读者解释现场。若反应重要，写具名人物真正做了什么；不重要就删。
5. 不写“四个女孩也没有闲着”“连她也能”“并非毫无用处”。直接写“四个女孩各自忙着……”并给出动作。
6. 不为显得利落，把所有对白压成一问一答和一两句命令。身体、身份、危险允许时，人物应当说完整；疼痛、战阵、追杀时才自然缩短。
7. 慎用并连续统计：`不是A，不是B，只是C`、`没有A，也没有B`、`她看的是……`、`念头落定`、`话落定`、`目光一沉`、`微微`、`众人震惊`、`无人知晓，一个时代开始了`。
8. 不能靠机械换动词修复模板。若段落骨架仍是“全场停下—主角说理—众人折服—作者总结”，即使把“停”换成“顿”、把“震惊”换成“失声”，仍判失败。
9. 叙述“上一世”“来到这里以前”，不要让刚穿越的人空泛说“很久以前”，除非时间在角色主观上确实已经很久。
10. 正文叙事中的发生次数用“趟、次、拨”，不要把小说回目术语“第N回”混作日常计数。
11. 不为假利落漏掉“了、着、过”和结果补语。朗读`往后也别谈带兵了`、`已经送到了`、`话还没说完`一类句子，删去虚词后若像提纲或话未说尽，必须恢复。
12. 连续三组以上“一问一答”须停检：只有刑问、诊病、核军情可以保留事实核对结构；家庭、照料、闲谈和共同做事必须改成自然接话、动作插入、犹豫或共享前情，不能人人像在录口供。
13. 每个工作单元和正式章必须直接核对`01_规则库/07_语言与风格/01_对白去AI官方腔词典.md`与`02_旁白去AI官方腔词典.md`。只读09号摘要、只搜禁词或只写“参照过”均不算执行。
14. 对白中`了、着、过、呢、吧、啊、才、才行`以及`到、完、下来、起来`等按完成、变化和语气判断；不设数量配额。旁白也不得为了“利落”删成残句。

## 四、结构与连续性防复发

1. 同一人物已经在场，不得下一段又写“恰好来探望”“刚从外面进来”，除非前文明确离场。
2. 同一动作必须由身体上能完成的同一人连续做完；换人、放手、接物和转身都要有动作桥。
3. 不得用未铺垫的回忆临时解决危机。记忆必须已有来源，或在当前场景通过物件、气味、话语合理触发。
4. 相邻工作单元不得都以睡去、梦境、醒来、月光、脚步声、门外有人、收到急报收尾。结尾要由当单元不可逆变化决定。
5. 跨章节复制段落、复述上章结尾和重新介绍熟人，只保留新读者真正需要的最少信息；重复出现必须增加意义。
6. 精确数字、日期、月相、农时、旅行、河流上下游、道路距离、官职变化和战争调动，必须能在年表、地图、台账或研究卡中复核。
7. 人物使用与时代、地区或世界观不符的生活习惯前必须核资料；无依据不得作为随手动作。
8. 人物姓名不能用`赵大、钱二、孙三`等占位符直接交付。确需乳名、排行、诨号，要有人物身份与形成原因。
9. 连续若干单元不能只换项目名称却重复同一发动机。家庭低场、调查、技术试验、利益争执、旅途、灾情、战阵、宗教仪式、教育和普通人后果应按故事需要轮换；轮换不是机械配额，但同一种结构再次出现必须升级风险、关系、权限或认知。
10. 配角存在性检查：删掉某个具名角色后，若其专业判断、利益、选择和后果都可由主角一句话替代，此人只是道具。应给他独立目标和不可替代行动，或删并角色，不能靠增加姓名假装群像。

## 五、机械扫描候选项

机械扫描至少检查：

1. ASCII直引号、英文单词、异常控制字符、乱码和意外制表符；时代内专名或单位确需英文时登记原因。
2. 连续高频：`体系|机制|推进|落地|闭环|赋能|抓手|路径|维度|层面|问题在于|这意味着|由此可见`。
3. 结构拐杖：`不是.*而是|没有.*也没有|只见|不由得|微微|众人.*震|没人.*问|都停下`。
4. 动态模板：相邻章节相同首句、相同末句、相同长度很高的段落、同一信息重复出现。
5. 项目禁误词：核对项目专属禁用词、时代称呼、专业称呼和身份差异；不能拿现代统称覆盖角色实际用语。
6. 数字和标题：工作单元不以字数判生死；正式章才核{{正式章字数下限}}—{{正式章字数上限}}字；卷末正式章名必须含`{{卷末标记}}`。

扫描命中只表示“需要人工看”，不表示自动删除；扫描不命中也不表示通过。

## 六、老书虫与小白双门复读

### 老书虫门

- 是否提前猜到每段都按同一模板走？
- 是否看见作者在硬铺垫、硬煽情、硬解释和故作深沉？
- 是否有可以整段跳过而不损失故事的信息？
- 人物是否只为抬主角、递问题、赞成或反对而存在？
- 章末是不是又用一句宏大判断代替真实后果？

### 小白门

- 不看规则表，能否认清此刻是谁、在哪里、为什么做这件事？
- 新名词是否由现场用途解释，而非一口气讲百科？
- 转场、传话、时间跳跃和人物称呼是否一遍可懂？
- 时代感是否来自物件、礼数和选择，而非堆生僻词？

两门必须分别记录具体卡顿和修复。不得只写“读起来很顺”“已去AI味”。

## 八、逐句完整性硬停

本文件负责告诉审稿者“查什么”，`00_项目入口/20_全卷正文生产流程.md`负责证明“所有规则文件都判断过是否适用”，`00_项目入口/19_逐句核验与卷终复核规则.md`负责证明“每一句都查到了”。三者必须同时执行：

1. 禁止只在卷卡写“称谓通过、对白自然、知情通过”而没有逐句触发码和正文行号。
2. 对白最低核`D1+D4+D7`；家庭、照料和闲谈另核`D5`。旁白最低核`N1+N2+N3+N5`。人物动作最低核`A1`。
3. `妖、反、逆、通敌、祥瑞、天命`等重词首次出现，必须在对应句行填写来源和后续承接；不得只靠全书搜索0次或1次宣告合理。
4. 逐句表有一个`待核／待填／需改／阻断`，正文就不通过；卷卡没有权力把它汇总成通过。
5. 逐句核验后正文改一个字，旧SHA和旧结论自动失效；修复范围至少包括改句前后、完整场景、后文同一信息和全文复读。
6. 正式章由工作单元重组而来时必须重建逐句表。章界变化会改变铺垫与承接，工作单元旧通过不能继承。
7. 机械脚本只核句子数、唯一编号、状态是否填完和SHA是否一致；脚本显示结构通过，也不代表对白、因果和读者体验通过。
